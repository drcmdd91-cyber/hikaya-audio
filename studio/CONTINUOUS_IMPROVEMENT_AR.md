# سياسة التطوير المستمر — دفتر الحكايات

## الدورة الإلزامية بعد كل فيلم
مشكلة ← تجربة حل ← اختبار النتيجة ← حفظ الحل ← منع تكرار المشكلة ← تطوير الأداة ← إضافة قدرات وقوالب جديدة ← اختبار التحسين ← إصدار جديد.

1. سجل كل خطأ وسبب حدوثه ودليل اكتشافه.
2. اختبر البديل فعليًا ولا تعتبر مجرد كتابة الشيفرة نجاحًا.
3. أضف اختبار انحدار يمنع تكرار المشكلة.
4. حسّن محركات الإنتاج والقوالب والأصول القابلة لإعادة الاستخدام.
5. قارن الفيلم الجديد بالسابق: مطابقة الصوت والصورة، جودة المشاهد، النطق العربي، جودة الأغلفة، زمن الإنتاج، وعدد الأخطاء.
6. وثّق التغييرات في CHANGELOG.md والدروس في LESSONS_LOG.md.
7. لا تعتمد إصدارًا جديدًا قبل نجاح الاختبارات المتاحة ومراجعة العينة البصرية والصوتية.
8. لا تنشر فيلمًا إلا بعد اجتياز بوابات الجودة والتحقق من النشر.

## أمثلة إضافات تراكمية
- مكتبة مشاهد سينمائية ومؤثرات وعدسات وانتقالات.
- قوالب غواصات وطائرات ومبانٍ وتشريح علمي ورسوم بيانات.
- أصوات شخصيات عربية مستقلة ومؤثرات راديو.
- أدوات تزامن دقيق بين المشهد والراوي.
- توليد أغلفة مميزة لكل جزء.
- فحص آلي للأخطاء مع مراجعة بشرية للمعنى البصري.

## مقياس التقدم
لا تساوِ بين الخطة والتنفيذ. لكل قدرة حالة واحدة: مقترحة، مبنية، اختبرت، جاهزة للإنتاج. مع تسجيل أدلة الاختبار وتاريخ الإصدار.
